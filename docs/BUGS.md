# Живые баги

## BUG-1: цикл перезагрузок, «логин не работает» — FIXED (PR #4)
Симптом: у гостя страница бесконечно перезагружалась (`/` → `/login` → …,
~10 запросов/с к `/api/v1/config` → 401), форма логина сбрасывалась,
POST логина обрывался перезагрузкой. Воспроизводилось и на проде
(`https://lab.iig.ru/3Row/`).

Корень: `/config` лежал внутри `auth:sanctum`, а фронт тянет конфиг до
авторизации; `api-client.js` диспатчил `auth:logout` на ЛЮБОЙ 401,
`auth.js` на это событие делал `location.href = /login` → перезагрузка →
цикл.

Исправление: `/config` вынесен из sanctum-группы (контроллер публичный);
`auth:logout` диспатчится только при 401 с токеном; бамп `?v=20261013a`.
Проверено headless-браузером: 1 навигация, `/config` 200 у гостя,
логин → меню → карта → уровень → свап (ходы 23→22, счёт 0→60),
0 ошибок консоли.

Заодно в том же PR: `.auth-screen` больше не перебивает `.screen { display: none }`
(форма логина висела поверх всех экранов, доска уезжала за нижний край).

## BUG-2: цвет центральной части спрайта после каскада (open, не воспроизводится)
Симптом: после каскада спрайт в центре неверно переключает цвет.
Источник: `public/assets/js/game_engine_pixijs.js` ~стр. 660–683
(`spTile.color = -1` + пересоздание спрайта special tile).
Воспроизведение: собрать матч 4+ в ряд, смотреть цвет центрального
special-спрайта после каскада.

Статус: 2026-10-14 не воспроизводится (владелец не наблюдает).
Смежный баг «DISCO не расходовался» исправлен в PR (fix/disco-consumed).
Если глюк цвета проявится снова — снять скриншоты до/после каскада
и записать шаги (тип special, длина матча, номер уровня).

## BUG-3: жизни не списывались при поражении — FIXED (feat/boosters-shop-bugs)
Симптом: проиграл уровень → счётчик жизней не менялся.
Корень: жизнь списывалась (`lives−1`), но `last_life_regen_at` не сбрасывался;
реген (+1 каждые 180 мин) при следующем же запросе `/user/progress` мгновенно
возвращал жизнь — трата маскировалась.
Исправление: при поражении `last_life_regen_at = now()`; жизнь −1 ровно раз за
факт поражения; регрессионный тест LevelLivesDefeatTest.

## BUG-4: поражение открывало следующий уровень — FIXED (feat/boosters-shop-bugs)
Симптом: проиграл 66-й → на карте открыт 67-й, непройденный помечен пройденным.
Корень: в `LevelController::complete` fail-ветка писала `max_level_reached = id+1`
(историческое «открывать следующий при фейле»).
Исправление: разблокировка/звёзды/прогресс — только при победе; поражение: −1 жизнь,
текущий уровень тот же; на фронте кнопка «Следующий» только при победе (иначе «Заново»);
регрессионные тесты LevelLivesDefeatTest.

Смежно исправлено в том же релизе: покупка товаров категорий «жизни/бусты» списывала
монеты и ничего не давала; покупки без транзакции/идемпотентности (теперь
`wallet_transactions`-ledger, `client_request_id`, lock).
